=== Baggage Tags

Both the Brave and OpenTelemetry bridges support copying selected baggage values to span tags.
Configure the desired field names through the `tagFields` constructor argument of `BraveBaggageManager` or `OtelBaggageManager`.
Remote propagation and span tagging are configured separately: configuring a remote field does not by itself configure a span tag.

When a span is in scope, `createBaggageInScope(name, value)` applies the value as a tag to that span if the field is configured for tagging.
Retrieving baggage with `getBaggage(...)` or reading its value with `get()` does not tag the span.

For example, with `locale` configured as a tag field and a span already in scope:

[source,java]
----
try (BaggageInScope baggage = tracer.createBaggageInScope("locale", "fr-FR")) {
    // The span is tagged with locale=fr-FR, and the baggage is available here.
}
----

Closing the baggage scope restores the previous baggage; it does not restore the span's previous tag value.
If a nested baggage scope changes the same tag, that tag retains the nested value after the scope closes.

NOTE: Tagging through an existing baggage handle differs between bridges.
Brave captures the current span when the handle is obtained and uses that span when setting a value; its no-argument `makeCurrent()` does not apply tags.
OpenTelemetry applies tags to the span current when a value is set or the handle is put in scope, including through no-argument `makeCurrent()`.
Use `createBaggageInScope(name, value)` at the point of use for the common behavior shown above.

With OpenTelemetry, configure a `BaggageTaggingSpanProcessor` on the `SdkTracerProvider` to tag spans with baggage already present when they start.
This also covers baggage extracted from incoming requests, without requiring a baggage lookup in application code.

== Aspect Oriented Programming

Micrometer Tracing contains `@NewSpan`, `@ContinueSpan`, and `@SpanTag` annotations that frameworks can use to create or customize spans for either specific types of methods such as those serving web request endpoints or, more generally, to all methods.

WARNING: Micrometer's Spring Boot configuration does _not_ recognize these aspects on arbitrary methods.

An AspectJ aspect is included. You can use it in your application, either through compile/load time AspectJ weaving or through framework facilities that interpret AspectJ aspects and proxy targeted methods in some other way, such as Spring AOP.

NOTE: `SpanAspect` requires AspectJ (such as `org.aspectj:aspectjweaver`) and an AOP Alliance implementation (such as `org.springframework:spring-aop` or `aopalliance:aopalliance`). Both are optional dependencies of `micrometer-tracing` and must be provided on your application's classpath.
